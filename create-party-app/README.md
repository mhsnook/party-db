# create-party-app (spike)

A backend made of Cloudflare parts, wired together so an app gets what `supabase-js` gives it:
a database, auth, file storage, image resizing, server functions and realtime. There is no
generic query builder. The client calls server functions you write, so each route's SQL is
also its access check.

| Need | Part |
| --- | --- |
| Database | D1, with plain `.sql` migrations |
| Server functions | Hono routes on one Worker, typed to the client through `hc` |
| Auth | better-auth, stored in the same D1 database |
| Files | R2; uploads stream through the Worker |
| Image resizing | the Images binding |
| Realtime | one Durable Object room per user (partyserver), pushing committed rows |
| Client data | TanStack DB collections over the server functions (`queryCollection`) |

Everything runs locally under `vite dev`, with no Docker and no cloud account.

## Start

```sh
pnpm install
cp .dev.vars.example .dev.vars
pnpm db:migrate   # applies migrations/ to the local D1
pnpm dev          # http://localhost:5173
pnpm e2e          # with dev running: two tabs, every write checked end to end
```

Browse local data in Local Explorer at `http://localhost:5173/cdn-cgi/local/explorer`. It covers
D1, R2 and the Durable Objects, and it has a REST API at `/cdn-cgi/local/explorer/api`.

## Deploy

```sh
pnpm deploy                 # creates D1 and R2 on first deploy; the bindings carry no ids
pnpm db:migrate:remote
npx wrangler secret put BETTER_AUTH_SECRET
npx wrangler secret put BETTER_AUTH_URL   # your deployed origin
```

The deploy has only been dry-run (`wrangler deploy --dry-run`), not run against an account.

## Layout

| Path | What it holds |
| --- | --- |
| `migrations/` | the schema. `0001_auth.sql` is generated by the better-auth CLI; the rest is yours. |
| `shared/schema.ts` | Zod schemas both halves import |
| `worker/api.ts` | the server functions (Hono), and the only place SQL runs |
| `worker/auth.ts` | better-auth over the `DB` binding |
| `worker/index.ts` | routes sockets to the realtime room and everything else to Hono |
| `src/app.ts` | the client: collections, auth client, storage helpers, all in one `app` |
| `party-app/` | the part that would become a package: `createApp`, `serverCollectionOptions`, `connectRealtime`, `publish`, `RealtimeServer` |

## How a write travels

1. `app.db.todos.insert(row)` shows the row at once and calls the collection's `onInsert`.
2. `onInsert` calls `POST /api/todos` through the typed `hc` client.
3. The route runs `insert … returning` against D1, then `publish()`es the returned row to the
   user's room.
4. The room sends that row to every socket the user has open.
5. `onInsert` writes the returned row into the collection, so the optimistic row settles without
   a refetch. Other tabs apply the same row from the socket.

## What realtime does not promise

This is the light tier. Each item is a known edge, not a bug:

- If the socket drops, frames sent in the gap are lost. On reconnect each loaded collection
  reloads once.
- Two tabs writing the same row at the same moment can publish out of order. A frame carries
  the whole row, so a late frame shows the older version until the next write or reload.
- A write that skips `publish()` (a cron job, an edit in Local Explorer) reaches open tabs only
  on their next reload.
- Rooms are per user. For a shared room, pass `roomOf` to `createApp`, and check membership in
  `onBeforeConnect` in `worker/index.ts`.

[party-db](https://github.com/mhsnook/party-db) is the upgrade for the first two: a commit-log
cursor, delta replay on reconnect, and writes serialized per room.

## Not built yet

- Presigned R2 uploads, for files past the Worker request-body limit (100 MB on Free and Pro).
  The R2 binding cannot sign URLs, so this needs R2 S3 API credentials as a secret.
- A smaller Worker. better-auth's SQLite introspector is ≈95 KiB of the gzipped upload;
  `better-auth/minimal` drops it but needs an explicit Kysely adapter for D1.
- Password hashing cost on the Workers Free plan. better-auth hashes with scrypt in JS, which
  may exceed the Free plan's CPU limit. This is untested.
- A TanStack Start variant that uses `createServerFn` in place of Hono, for SSR with query
  hydration.
- The `create-party-app` CLI that copies this template.
